# Excel・Word の差分表示の仕様と検査

導入と使い方の手順は setup-notes の[excel-diff を導入・更新する](https://github.com/ryo-aoki-pc/setup-notes/blob/main/docs/almalinux-setup.md#excel-diff-を導入更新する)（Windows 11 は[同名の項](https://github.com/ryo-aoki-pc/setup-notes/blob/main/docs/windows-setup.md#excel-diff-を導入更新する)）と、その後ろの項にある。この文書には、Excel・Word の表示する内容・取り込みと Word の部分ステージの仕様・自動検証・macOS の導入を置く。対応条件と制限は[注意点](../extra/readme.md)。

## 表示する内容

次の表は、通常の Git の差分表示（textconv）の対象です。

| 形式 | 表示内容 |
| --- | --- |
| `.xlsx` / `.xlsm` / `.xltx` / `.xltm` | 全シートのセル値、セル番地、数式。数式は式そのものを表示し、再計算しない |
| `.xls` / `.xlt` | 全シートのセル値、セル番地。数式セルはファイルに保存された計算結果を表示する |
| `.docx` / `.docm` / `.dotx` / `.dotm` | 本文・ヘッダー・フッターの段落、表、直接指定した書式など。脚注・文末脚注・コメントも表示する |

拡張子の大文字・小文字はどちらも対象です。Git が過去の版を拡張子の無い一時ファイルに取り出す場合も、内容から形式を判定して変換します。

例えば、売上シートの B2 を `1000` から `1200` に変えると、Git の差分は次のようになります。delta では削除側と追加側が左右に並びます。

```diff
 Sheet: "売上"
 A1	"金額"
-B2	1000
+B2	1200
 C2	formula: "=B2*1.1"
```

通常の Git の差分表示（`excel-textconv.py`）では、空のセルを省略します。文字列中の改行やタブは `\n` / `\t` として表示し、1 セルを 1 行で比較します。書式・色・図・マクロのコードは比較しません。`.xlsb` とパスワードで暗号化されたブックは対象外です。

Excel の部分ステージと取り込みの画面では、セルの値・通常の数式に加え、セルの書式も比較します（[Excel のセルの書式の比べ方](#excel-のセルの書式の比べ方)）。値と書式は別々に選べます。値の無い書式付きのセルも対象です。値の行は、書式の違いの有無によらず同じ形式です。

### Word の表示

`.docx` / `.docm` / `.dotx` / `.dotm` は、Transitional 形式の OOXML を対象にします。段落は 1 行で、明示したスタイルがあるときは `[スタイル名]`、続いて JSON の文字列と書式を表示します。書式を直接指定していない段落は、書式を表示しません。

```text
# 本文
[heading 1] "はじめに"
"この文書は、見積の手順を示す。重要な点は太字にする。" 太字「見積」 #4bee1058
"対象は社内と協力会社の利用者とする。"
[List Paragraph] "見積書を作る" 箇条書き「●」L1 #e38d8803
表 "3×2" 幅 罫線 #1b89e199
  行 R1 "" #f177afe4
  R1C1 "項目" #7ef80f06
```

- 本文は `# 本文`、ヘッダー・フッターは `# ヘッダー（セクション 1・既定）` などの見出しで分ける。先頭ページ・偶数ページの区別も表示する
- 表は `表 "3×2" …` に続けて、行の設定を `行 R1 "" …`、セルを `R1C1 "項目" …` の形で表示する。セル内の複数段落は文字列中の `\n` で表す
- 書式は太字・色・サイズ・配置・画像・リンク・フィールドなどの要約と、正規化した構造を識別する `#` で始まる 8 桁のハッシュで表す。同じ文字のまま書式だけを変えた場合も違いが出る
- 箇条書き・段落番号の行頭文字に使う記号フォントの文字は読める文字に置き換え、置き換えられない文字は `\uXXXX` で表す
- 文字列中の改行・タブは `\n` / `\t` として表示する。U+0085・U+2028・U+2029 もエスケープし、1 行の途中で改行されないようにする
- 脚注・文末脚注・コメントは末尾の `# 脚注`・`# 文末脚注`・`# コメント` に、参照順の番号と内容を表示する。コメントには作成者と日時も表示する。文書パーツがあれば `# 文書パーツ: 名前` の後ろに表示する

Word が保存時に付ける編集 ID、校正の印、言語指定、最終描画時の改ページ、隠しブックマークなどは比較から除きます。同じ書式の文字の分割を揃え、関係 ID は画像の内容やリンク先、スタイル ID は名前と種類、番号 ID は定義の内容で比べます。スタイル定義を展開して見た目を計算することや、箇条書きの番号を計算することはしません。

大きい文書の変換が 2 秒以内に終わらない場合は、次の仮の内容を返して裏で変換を続けます。文書内の XML を展開した大きさから時間がかかると分かる場合も、待たずに返します。完了後はファイルを選び直すか `R` で表示します。待つ時間は Excel と同じ環境変数 `EXCEL_TEXTCONV_TIMEOUT` で変えられます。

```text
# Word を裏で変換中 (1a2b3c4d5e6f)
# 完了後に選び直すか R で表示
# 本文
```

変換に失敗した場合は `Word の差分変換に失敗しました: …` と理由を表示します。暗号化された文書と `.doc`、Strict 形式は対象外です。電子署名付きの文書は差分を表示できますが、部分ステージと取り込みはできません。

## Excel のセルの書式の比べ方

Excel の部分ステージでは index と作業中のブック、2 つのブックの取り込みでは取り込み先と取り込み元のブックを比べます。対象は表示形式・フォント・塗りつぶし・罫線・配置・保護・セルのスタイルです。行の高さ・列の幅・行や列そのものの書式・条件付き書式・リッチテキストの文字ごとの書式・テーマそのものは対象外です。

セルの要素がある場合は、そのセルの書式番号（省略時は 0）を使います。セルの要素が無い場合は、行の書式（`customFormat` が有効なもの）、列の書式、既定の書式の順で受け継ぎます。行・列の書式は、セルが受け継いだ書式を判断するために読み、行・列の設定自体は反映しません。

書式番号ではなく、参照先の中身で比較します。既定値の省略、`applyX` の指定、色の ARGB の先頭 2 桁（アルファ）、`<b/>` と `<b val="1"/>`、数値の `11` と `11.0` は同じとみなします。セルのスタイルは、組み込みなら `builtinId`、それ以外は名前で識別します。テーマ色はテーマ番号と濃淡を比べ、テーマの定義自体は比べません。

組み込みの表示形式のうち、言語に左右されない番号（0〜4・9〜13・20・21・45〜49）は書式の文字列で比較します。それ以外は `組み込み14` のように番号で表示します。同じ文字列の独自の表示形式と、言語に左右されない組み込みの表示形式は同じとみなします。

書式の行は、両側で書式が違うセルだけをセル番地順に並べ、行の間に空行を 1 行挟みます。書式の行はどれも両側で違うので、空行が無いとシートの書式の違い全体が lazygit の 1 つのハンク・WinMerge の 1 つの差異になり、セルごとに選べません。行は次の形です。

```text
["B2","format","太字、文字色=#FF0000、塗りつぶし=単色、塗りつぶしの色=#FFFF00"]
```

説明は index／取り込み先の既定の書式（`cellXfs` の 0 番）と違う項目だけを日本語で並べ、同じなら `既定の書式` とします。制御文字・U+0085・U+2028・U+2029 はエスケープして 1 行に収めます。中身が違うのに説明が同じになる場合は、両側に `[ハッシュ 8 桁]` を付けて区別します。

## Word の部分ステージ

### 対象

lazygit のファイル一覧の `E` は、Excel と同じ `git excel-stage` から Word の処理を開きます。`git word-stage -- "仕様書.docx"` も同じ入口の別名です。

- `.docx` / `.docm` / `.dotx` / `.dotm` の既存ファイルで、HEAD と index の両方にある、競合のない通常のファイルが対象
- すでにステージした変更があれば index の版を基準にし、残りの変更を追加する。新規ファイルは全体をステージする
- 作業中の文書は書き換えず、選んだ変更を Word の形のまま index に反映する。他のファイルのステージ内容は保つ
- 読み込み中は「Word を読み込んでいます。大きい文書では選択画面が開くまで時間がかかります。」と表示する

### 専用画面のファイルと行

本文・ヘッダー・フッターの部分ごとに、`001-本文.word.txt`、`002-ヘッダー（セクション 1・既定）.word.txt` などのファイルを作ります。番号は部分の順で、lazygit のファイル一覧には違いのある部分だけが出ます。閲覧用の textconv と違い、各行は 5 個の文字列を持つ JSON の配列です。変更後の版の行は、たとえば次のようになります。

```text
["4","paragraph","","この文書は、見積の手順を示す。重要な点は太字にする。","太字「見積」 #4bee1058"]
["5","paragraph","","対象は社内と協力会社の利用者とする。",""]
["6","blank","","",""]
["16 R2C2","cell","R2C2","120","#96ff0285"]
```

順に `[番号, 種類, スタイル名などのラベル, 文字, 書式]` を表します。種類は `paragraph`・`table`・`row`・`cell`・`section`・`content-control`・`other`・`blank` です。片方に無い内容も行を詰めず、`blank` の行を置いて左右の位置を揃えます。文書内の空の段落は `paragraph` で、`blank` とは別です。

番号は選択画面で対応する単位を示すもので、Word 内の段落 ID ではありません。通常は `12`、複数行のまとまりは `12/1`・`12/2`、分割できる表は `12 R1`・`12 R1C1` の形になります。行全体を元の行か変更後の行として選び、番号や JSON を手で書き換えません。

### 選べる単位と選び方

- 段落は 1 段落ごと。文字の変更に加え、太字や色など書式だけの変更も選べる
- 表は、両方の版で行・セルの数や結合の構成が同じで、安全に分割できる場合に、表の形・行の設定・セルごとに選べる。セル幅は表の形に属し、セルの文字だけを選んだ場合は元の幅を保つ
- 行を足した表や結合の構成が変わった表、セルをまたぐフィールドなどがある表は、表全体を 1 つのまとまりとして選ぶ
- 目次のように複数の段落にまたがるフィールドや範囲は、まとまり全体を選ぶ
- セクションの用紙・余白などの設定は段落と別の単位で選ぶ。既存のヘッダー・フッターの段落も選べる

`Enter` → `Space` でハンクを選び、`X` で反映します。置換は削除側と追加側の両方、まとまりは変更のある行をすべて選びます。一部だけを選ぶと「本文 2 の選択が不完全です。このまとまりの変更行をすべて選んでください。」のように表示して止まります。行を削除・追加したり、順番を変えたりした選択も反映しません。

反映後は「N か所の変更を Word のままステージしました。q で元の画面へ戻ってください。」と表示します。選択がない場合は反映しません。`X` の前に `q` で閉じれば取り消し、反映後は `q` で元の画面へ戻ります。

### 選べない違い

開始前に「部分ステージできない違い（N か所）: 本文 #12（理由）, …」の形で先頭 20 件までと残りの件数を端末へ出します。専用画面にも違いは表示しますが、その変更を選んで `X` を押すと「本文 12 は段落単位で反映できません: 理由」などと表示し、index は変えません。

主な理由は次のとおりです。

- コメント、脚注・文末脚注の参照
- グラフ・SmartArt・図形・テキストボックス・VML の図形や画像・埋め込みオブジェクト（OLE）・ActiveX コントロール・インク・3D モデル
- 変更履歴の移動、データにリンクしたコンテンツ コントロール、繰り返しセクション
- 取り込み先に対応する文書パーツがない、プレースホルダー表示中のコンテンツ コントロール
- 埋め込み文書（altChunk）・サブ文書・カスタム XML・未対応の要素
- セクション区切りの追加・削除、セクション区切りを含むまとまり、ヘッダー・フッターの追加・削除や構成の変更
- 閉じていないフィールド、存在しないスタイルや番号定義への参照、対応できない参照やスタイルの構成

こうした変更をステージする場合は、元のファイル一覧で文書全体をステージします。

### 作り直しと検証

選んだ段落・セル・表などの XML を写し、そこで使う画像・外部リンク・新しいスタイル・箇条書きと段落番号の定義も一緒に写します。選ばなかった部分と、変更しない ZIP 内の部品は元のものを保ちます。

スタイルは名前と種類で対応させ、取り込み先に無いものだけを依存するスタイルと一緒に写します。同じ名前の既存定義は上書きしません。画像と番号定義は同じ内容があれば再利用し、新しいものは既存の名前や ID とぶつからないよう追加します。関係 ID、ブックマーク、変更履歴、描画などの ID も衝突を避けます。

作り直したバイト列を再び読み、選択から期待される表示内容、画像・リンク・スタイル・番号定義の参照先、ID の重複、範囲やフィールドの開始と終了、本文やセルの末尾の段落などを検証します。検証に失敗した場合は「作り直した Word 文書の検証に失敗しました。書き込みは行っていません」などの理由を表示し、index を変えません。

反映前には、保存した写しと選択画面の控えを SHA-256 と文書から作り直した行で照合します。index の対象ファイルや作業ファイルが選択開始後に変わっていた場合も止まります。画面を閉じ、`E` から開き直してください。

### 目次などの参照先

目次や相互参照などのフィールドを更新する処理はありません。取り込み元の目次などを選び、その参照先の隠しブックマークが無くなる場合は、両方の版にあり、表示が同じ未選択の段落などを取り込み元のものに置き換えることがあります。対応できない要素を含まず、元に残す参照先も壊さないことを確かめてから置き換えます。表示に違いがある単位を暗黙に選ぶことはありません。

置き換えたときは「目次などの参照先に合わせて、表示が同じ N か所を取り込み元のものにしました。」と表示します。これは部分ステージと取り込みの両方で行います。

参照先が無くなる選び方は `目次の参照先「名前」が見つからなくなります。参照先の段落の変更も選んでください。` などの理由で止まります。相互参照・文書内リンクも同様です。

## 2 つのブックの取り込み

`git excel-merge [--tool auto|winmerge|lazygit] [--] <取り込み先> <取り込み元>` は、最初の引数のブックを上書きします。Git のリポジトリの外でも使えます。絶対パスはそのまま、相対パスは起動時の作業フォルダーに `GIT_PREFIX` と引数を足した場所として解釈します。画面を開く前に、取り込み先・取り込み元の絶対パスと、取り込めない違いの一覧を端末へ出します。

### 対象

- 両方とも `.xlsx` / `.xlsm` / `.xltx` / `.xltm`。拡張子の組み合わせは問いません。
- シートの名前・順序・ブックの中の参照（シートの部品の名前と関係 ID）、日付基準、名前定義、外部参照が同じブック。片方をもう一方から「名前を付けて保存」などで作ったブックを想定しています。異なる場合は、その項目を示して止まります。
- 取り込むのはセルの値・通常の数式と、選んだセルの書式です。値と書式は別々に選べます。選ばなかったセルの書式・画像・マクロ・テンプレート形式は取り込み先のものを保ちます。数式は計算しません。
- 同じファイル同士は指定できません。パスの表記違い、シンボリックリンクやハードリンクを介して同じファイルを指す場合も対象外です。

リッチテキスト、共有数式・配列数式などの範囲、結合セルの左上以外など、セル単位で反映できない値の内容は両側のブックで調べます。これらのセルでも、セルの書式は別に比較・選択します。

書式では、次のものを反映できません。

- セル内のチェックボックスなど、xf の `extLst` にある拡張機能。
- 範囲外・不正な書式番号や参照番号、定義の無い独自の表示形式。
- コピーが必要なフォント・塗りつぶし・罫線・表示形式・スタイルの定義に含まれる拡張の名前空間。
- 両方のブックでパレットが違う場合の、パレット番号で指定した色。
- 取り込み先に同じ名前で中身の違うスタイルがあり、新しいスタイルのコピーが必要な場合。
- 取り込み先に styles.xml や主要な要素が無い場合、またはコピー後の `cellXfs`・`cellStyleXfs` が 64000 件を超える場合。

取り込み先に完全に同じ中身の xf があれば、新たな定義をコピーせず再利用します。ただし、xf の `extLst` は再利用の場合も対象外です。

反映できない値や書式は、その行の取り込み元の表示も取り込み先と同じにして、選択対象から外します。端末には `シート名!A1（理由）` の形で先頭 20 セルまでと残りの件数を出します。同じセルに複数の理由がある場合は `・` でつなぎ、1 セルとして数えます。部分ステージでは書式の行を表示した上で、対応できない書式を選んで `X` を押すと、index を変えず理由を表示して止まります。

値・数式・書式のどれにも違いがなければ、画面を開かず「差分がありません」で終わります。取り込めない違いだけの場合も、件数を表示して画面を開かず終わります。

### 道具の選び方

| `--tool` | 選ぶ画面 |
| --- | --- |
| `auto`（既定） | Windows で WinMerge が見つかれば WinMerge。それ以外は lazygit |
| `winmerge` | WinMerge。見つからなければ導入を案内して止まる |
| `lazygit` | lazygit の専用画面 |

WinMerge は、レジストリの `HKCU`、`HKLM` の順で `Software\Thingamahoochie\WinMerge` の `Executable`、`%LOCALAPPDATA%\Programs\WinMerge\WinMergeU.exe`、`%ProgramFiles%\WinMerge\WinMergeU.exe`、PATH の順に探します。lazygit を選んだときは lazygit 0.66.0 以上と delta 0.20.1 以上を確かめます。WinMerge では、この 2 つを使いません。

### WinMerge のテキストと照合

一時フォルダーの `winmerge/取り込み先.cells.txt` を左、`winmerge/取り込み元.cells.txt` を右に開きます。左の控えは `baseline/取り込み先.cells.txt` に置き、SHA-256 をセッションに保存します。書き出すテキストは UTF-8 の BOM 付き、LF、最終行にも LF を付けます。

```text
# 右（取り込み元）から左（取り込み先）へ、取り込むセルの行をコピーする
# 上書き保存（Ctrl+S）してから WinMerge を閉じると、取り込み先のブックに書き込む
# シート 1: "売上"
["A1","string","金額"]
["C5","blank",null]
# 書式 シート 1: "売上"
["B2","format","太字、文字色=#FF0000"]

["C3","format","表示形式=「#,##0」"]
```

左右で見出しとセルの行の数・順番を揃え、両側のセル番地を合わせて並べます。各シートの値の前に `# シート N: <JSON のシート名>`、セルは `[セル番地, 型, 値]` の JSON で 1 行ずつ出します。片方に無いセルは `blank` と `null` で表します。書式に違いがあるシートだけ、値の行の後ろに `# 書式 シート N: <JSON のシート名>` と、空行で区切った書式の行を置きます。同じセルの値と書式は、それぞれの節で独立してコピーできます。文字列中の改行・タブに加え、U+0085・U+2028・U+2029 もエスケープし、1 セルが複数の行に割れないようにします。

WinMerge は独立したウィンドウで開き、終了まで待ちます。左は書き込み先、右は読み取り専用です。起動には `/s- /e /u /fl /wr /t text` と、左右のファイル名だけを含む見出しを渡します。比較の設定を上書きする `/cfg`・`/ignore*`・`/cp` は使いません。

窓を閉じた後、控えの改ざんを SHA-256 で検査し、保存された左と行ごとに照合します。見出しは控えと完全一致する必要があります。セルの行は、同じ位置の取り込み先の行か取り込み元の行のどちらかに完全一致する必要があり、後者だけを選択したセルとして扱います。

- 許すもの: BOM の有無、LF・CRLF・その混在、最後の改行の有無、末尾の空行。
- 止めるもの: UTF-8 以外の保存、見出しや書式の行の間の空行の変更・削除、行の増減・並べ替え、手で打った値や書式の説明、置換の片側だけの変更、別のシートや値・書式の異なる節への行のコピー。

何もコピーせずに閉じた場合や保存しなかった場合は、取り込み先を変えません。2 秒以内に終了して左も変わっていない場合は「WinMerge がすぐ終了しました」と警告します。照合に失敗したとき、端末では保存された左を保ったまま WinMerge を開き直して直すかを選べます。

### lazygit の専用画面

一時リポジトリの HEAD に取り込み先のセル、作業ツリーに取り込み元のセルを置きます。最初のコミット名は「取り込み先の Excel」です。部分ステージの専用画面と同様、シートごとの JSON の行を比較します。値・数式は `001-売上.cells.txt`、書式は `001-売上.formats.txt` のように別のファイルに置き、同じセルの値と書式を別々に選べます。書式のファイルには、書式が違うセルだけを空行で区切って並べるので、セルごとに別のハンクになります。

`Enter` → `Space` でハンクをステージし、`X` で選択したセルを取り込み先へ書き込みます。`X` の説明は「選択セルを取り込み先へ書き込む (反映後 q で戻る)」、結果の題は「Excel の取り込み」です。書き込む前に `q` で閉じると取り消し、反映後は `q` で元の画面へ戻ります。

選択がなければ書き込みません。値の置換と書式の変更は、それぞれ削除側と追加側の両方を選ぶ必要があります。一度反映したセッションの再反映、不正な選択、部分ステージ用セッションとの取り違えは止めます。書き込みに失敗したときは反映済みにしないので、原因を直して `X` で再試行できます。

### 取り込み先への書き込み

1. ブックを読む前に、取り込み先が通常のファイルで書き込み可能かを確かめます。シンボリックリンクと複数のハードリンクを持つファイルは対象外です。Windows は読み書き用に開けるか、Linux は LibreOffice のロックファイル `.~lock.<ファイル名>#` が無いかも確かめます。
1. 取り込み先・取り込み元の写しと SHA-256 を保存し、写しから選択画面を作ります。取り込み元は、この時点の写しを使います。
1. 選択された値・数式と書式を取り込み先の写しに反映し、作り直したブックを検証します。書式は取り込み先の同じ定義を再利用し、無ければ styles.xml の末尾に必要な定義を足します。既存の項目を並べ替えたり削除したりせず、未選択のセル・行・列の書式を保ちます。値・数式を変えた場合だけ `fullCalcOnLoad` を付け、次に Excel で開くときの再計算を指定します。値を選んだ文字列のふりがなは引き継ぎません。
1. 取り込み先と同じフォルダーに一時ファイルを作り、内容を書いて `fsync` し、閉じてから元のモードを写します。Windows は `Zone.Identifier` があれば写します。
1. 置き換える直前に取り込み先の SHA-256 を確かめ、準備時と同じ場合だけ `os.replace` で置き換えます。`PermissionError` は 0.2 秒おきに再試行し、そのたびに SHA-256 を確かめます。失敗した場合は書き込み用の一時ファイルを消します。

取り込み先が変更・削除されていた場合は上書きしません。書き込みの権限エラーが続く場合、端末では Excel などで取り込み先を閉じてから再試行できます。選択がない場合は元のバイト列・更新日時を保ち、書き込んだ場合は更新日時が新しくなります。バックアップは作りません。

## 2 つの Word 文書の取り込み

`git word-merge [--tool auto|winmerge|lazygit] [--] <取り込み先> <取り込み元>` は、最初の引数の文書を上書きします。`git excel-merge` と同じ入口の別名で、拡張子から処理を選びます。Git のリポジトリの外でも使えます。相対パスの扱いと `--tool` の選び方は[ブックの取り込み](#2-つのブックの取り込み)と同じです。

### 対象

- 両方とも `.docx` / `.docm` / `.dotx` / `.dotm` の Transitional 形式。拡張子の組み合わせや、同じ文書から作ったかどうかは問わない
- Excel と Word を混ぜると「Excel と Word は混ぜて取り込めません。同じ種類のファイルを 2 つ指定してください。」で止まる
- 同じファイル同士は指定できない。パスの表記違いや、シンボリックリンク・ハードリンクを介して同じファイルを指す場合も対象外
- 選んだ段落・セル・表・既存のヘッダー・フッターなどを取り込み元の書式で入れる。選べる単位、画像・リンク・スタイル・番号定義の扱い、作り直しの検証は [Word の部分ステージ](#word-の部分ステージ)と同じ

画面を開く前に、取り込み先・取り込み元の絶対パスと「取り込めない違い（N か所）: 本文 #12（理由）, …」を端末へ出します。取り込めない違いは両側とも取り込み先の行にして選択対象から外します。理由は部分ステージと同じです。

違いがなければ「差分がありません。取り込み先は変えていません。」、取り込めない違いだけなら「取り込める差分がありません（取り込めない違い N か所）。取り込み先は変えていません。」と表示し、画面を開かず終わります。

### WinMerge のテキストと照合

一時フォルダーの `winmerge/取り込み先.word.txt` を左、`winmerge/取り込み元.word.txt` を右に開きます。左の控えは `baseline/取り込み先.word.txt` に置き、SHA-256 を保存します。UTF-8 の BOM 付き、LF、最終行にも LF を付けて書き出します。

左右の見出しは「取り込み先（書き換える）: 仕様書.docx」と「取り込み元: 仕様書-更新.docx」で、右は読み取り専用です。

左のファイルの先頭は、次のようになります。右も同じ見出しで始まり、同じ位置に取り込み元の行が並びます。

```text
# 右（取り込み元）から左（取り込み先）へ、取り込む行をコピーする
# 上書き保存（Ctrl+S）してから WinMerge を閉じると、取り込み先の文書に書き込む
# 部分 1: "本文"
["1","paragraph","Title","仕様書",""]
```

部分ごとに `# 部分 N: <JSON の部分名>` を置き、JSON の行は専用画面と同じ形式で左右の位置を揃えます。改行・タブ・U+0085・U+2028・U+2029 はエスケープします。

取り込む行を右から左へコピーし、上書き保存（`Ctrl+S`）して窓を閉じます。その後、控えの SHA-256 と作り直した行を検査し、保存された左を照合します。見出しは控えと完全一致し、各行は同じ位置の取り込み先か取り込み元の行全体に一致する必要があります。取り込み元の行に変えた単位だけを選択として扱います。

- 許すもの: BOM の有無、LF・CRLF・その混在、最後の改行の有無、末尾の空行
- 止めるもの: UTF-8 以外の保存、見出しの変更、行の増減・並べ替え、手で打った文字や書式、置換の片側やまとまりの一部だけの変更、別の位置の行のコピー

何もコピーしなかった場合や保存せず閉じた場合は、取り込み先を変えません。照合で止まったときは、端末で WinMerge を開き直して直すかを選べます。起動時のオプションと比較設定の扱いは Excel と同じです。

### lazygit の専用画面

一時リポジトリの HEAD に取り込み先、作業ツリーに取り込み元の行を置きます。最初のコミット名は「取り込み先の Word」です。ファイル一覧は `001-本文.word.txt` など、部分ステージと同じ構成です。

`Enter` → `Space` でハンクをステージし、`X` で選んだ変更を取り込み先へ書き込みます。結果の題は「Word の取り込み」です。書き込む前に `q` で閉じると取り消し、反映後は `q` で元の画面へ戻ります。置換やまとまりの選び方も部分ステージと同じです。

### 取り込み先への書き込み

1. 文書を読む前に、取り込み先が通常のファイルで書き込み可能かを確かめます。シンボリックリンク、複数のハードリンク、読み取り専用のファイルは対象外です。Windows は読み書き用に開けるか、それ以外は LibreOffice のロックファイル `.~lock.<ファイル名>#` が無いかも確かめます。
1. 取り込み先・取り込み元の写しと SHA-256 を保存し、写しから選択画面を作ります。取り込み元は、この時点の写しを使います。
1. 選んだ変更と必要な画像・リンク・スタイル・番号定義を取り込み先の写しに反映し、作り直した文書を検証します。
1. 取り込み先と同じフォルダーに一時ファイルを作り、内容を書いて `fsync` し、閉じてから元のモードを写します。Windows は `Zone.Identifier` があれば写します。

取り込み先が変更・削除されていた場合は上書きしません。Word などで取り込み先を開いている場合は閉じてください。権限エラーが続く場合、端末では閉じてから再試行できます。OneDrive などの共同編集中かどうかは検出しません。

取り込み元は変更しません。選択がない場合は取り込み先の元のバイト列と更新日時を保ち、書き込んだ場合は更新日時が新しくなります。バックアップは作りません。

## 自動検証

自動検証は、このリポジトリのフォルダーで導入した仮想環境の Python を使って実行できます(既定の置き場所の例)。

Linux:

```sh
"${XDG_DATA_HOME:-$HOME/.local/share}/excel-diff/venv/bin/python" -B -m unittest discover -s tests -v
```

Windows(PowerShell):

```powershell
& "$env:LOCALAPPDATA\excel-diff\venv\Scripts\python.exe" -B -m unittest discover -s tests -v
```
